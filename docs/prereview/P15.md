## New correctness findings, ranked

### P15-1 — Medium — criteria-only search is silently dismissed by the tab reducer

**Location:** `Sources/HelmCore/State/TabSearch.swift:6`; entry route `Sources/HelmCore/State/TabReducer.swift:140`; typed input `Sources/HelmCore/Search/SearchContracts.swift:15`; comparison `Sources/HelmSearch/Query/SearchQueryParser.swift:27`.

**Wrong:** startSearch treats whitespace-only text as an empty query regardless of `query.filters`. The parser and saved-search editor support typed filters independent of text. A valid kind-only/tag-only Smart Folder cannot enter the overlay through the public reducer action: it restores ordinary directory contents instead of issuing a search. This is separate from P5-4's fixed Refresh behavior and K23's already-disclosed truncation loss.

**Concrete failing test (text only):** start a tab at `/work`, dispatch `searchStarted` with text `" "`, scope currentFolder, filters `[.kind(.regular)]`, then assert nonnil search, a startSearch effect retaining that filter, and a loading overlay. Current code produces none of those. Repeat while another query is active: replacing its name term with an empty string while retaining `.tag("Project")` must keep filtering, but currently ends search. A genuinely empty text+filters query must still end it. Add refresh of the filters-only query and stale-generation rejection controls.

**Exact fix:** end search only when trimmed text is empty **and filters is empty**. Preserve the same predicate anywhere a host translates criteria to search intent; do not synthesize a textual token or silently broaden invalid typed criteria. Keep parser validation/error reporting. Existing reducer search tests use nonempty text, and ContractIntegrationTests tests filter propagation through the compiler rather than this reducer boundary; they can all pass with this defect. Lane N2 below owns the repair and regressions.

### P15-2 — Medium — Properties still presents package metadata bytes as an unqualified contents size

**Location:** `Sources/HelmCore/Presentation/PropertiesModel.swift:26` and `:30`; `Sources/HelmUI/Properties/PropertiesViewModel.swift:35–41`; input `Sources/HelmFileSystem/Live/MetadataReader.swift:33–40`.

**Wrong:** directoryCount uses the navigation predicate isDirectoryLike, excluding packages. totalSize sums their raw directory metadata bytes. The UI adds its “folder contents not included” qualification only when directoryCount is nonzero. A package therefore appears as an ordinary file with a known, unqualified size, despite no recursive total. P10-3/F11 fixed this classification in accessibility speech only; this independent Properties path remains. F11's speech fix is valid, but does not close the product-wide size issue.

**Concrete failing test (text only):** supply `.package` `/Applications/Tool.app` with metadata size 4096 (conceptual contents 200 MB). PropertiesModel yields fileCount 1/directoryCount 0/hasUnknownSize false; PropertiesViewModel.size yields `"4096 bytes"`. Assert that raw package bytes cannot be presented as known contents size. Cover a regular file plus a package, actual directories, and a separately supplied completed recursive total. No measured Mac directory-size value is asserted here; 4096 is an injected fixture.

**Exact fix:** use a size-specific classification, independent of navigation. Mark package contents unknown/calculating until a trusted recursive result is supplied; exclude raw package directory bytes from known contents totals, and qualify the mixed-selection display. Keep isDirectoryLike unchanged so packages still open rather than navigate. Align the future size-session projection with InspectorSizeState. Existing Properties tests cover regular files and a directory, but no package; the ordinary-directory test explicitly expects raw metadata in its legacy aggregate. Preserve or explicitly migrate that documented legacy field; do not silently redefine it as recursive bytes. Add an independent package expectation in both Core and portable Properties adapter tests. Lane N3 owns this repair.

No new critical/high safety defect, actor race, unsafe Sendable conformance or confirmed macOS SDK misuse was established. Native mutation receipts, tree verification, lifetime wiring and Mac SDK acceptance remain inherited risks; this is not a clearance of them.

## Eight prioritized, non-conflicting next-wave build lanes

These are proposed assignments, not work performed or approval to enable external actions. All new API values named in Core signatures must live in Core, with explicit public initializers and Sendable actor-crossing values. Use existing Foundation-only targets and XCTest targets: **no Package.swift changes**, AppKit, Combine, macros or new dependency edges. Each lane owns only the listed paths; all other existing contracts are read-only. New directories below are deliberately separate. A subsequent serial integration owner wires menus/store/host and updates the ledger from real assertions. It must not claim native parity from these models.

### N1 — Undo/redo history ownership (highest daily-workflow value; bounded medium task)

- **Own:** new `Sources/HelmCore/OperationHistory/`, `Sources/HelmOperations/History/`, `Tests/HelmCoreTests/OperationHistoryTests/`, `Tests/HelmOperationsTests/HistoryTests/`. Read existing Journal/Undo/Executor; do not change them or AppEnvironment.
- **API sketch:** Core `OperationHistoryState`, `HistoryRequestID`, `HistoryAction`, `HistoryEffect`, and reducer; Operations `WindowOperationHistory` actor maps existing JournalEntry/OperationResult to it. Separate original operations from inverse/redo attempts. `beginUndo()` reserves one entry/request; `complete(request:outcome:)` accepts once. Redo is a fresh validated operation from recorded intent, never blind replay of stale path steps.
- **Deliver:** named per-window undo/redo availability, busy gate across suspension, new-forward-operation redo invalidation, explicit partial/failure/refusal states. No durable journal, tree-undo relaxation or provider changes. If safe redo cannot be constructed for a command, expose unsupported rather than claiming completion.
- **Tests:** independent windows; inverse entries never become new user operations; double-click/concurrent undo admits one request; stale completion; new edit clears redo; partial failure retains reconciliation; leaf refusal remains refusal; text focus is a host routing obligation. Build HelmOperations; filter HelmOperationsTests/HelmCoreTests as appropriate.

### N2 — Search/Smart Folder session bridge and criteria admission (medium)

- **Own:** new `Sources/HelmCore/SearchSessions/`, `Sources/HelmSearch/Sessions/`, `Tests/HelmCoreTests/SearchSessionTests/`, `Tests/HelmSearchTests/SessionTests/`; existing `Sources/HelmCore/State/TabSearch.swift` solely for P15-1. No other lane touches State.

Reuse SearchService/SearchEvent, query compiler and codecs. A `SavedSearchOpenPlan` distinguishes editable Helm definition from opaque Finder document and carries definition URL separately from result URLs.
- **Deliver:** latest-only event admission, filters-only start/refresh, honest completion/truncation/disclosure, safe definition-open intent. Limit to existing AND grammar; no RawQuery interpreter or NSMetadataQuery adapter. Keep persistence injection as Data/URL values or Core-owned protocol, not Search→Persistence import. Envelope-to-TabAction changes remain a serial integration follow-up.
- **Tests:** empty text with kind/tag criteria; truly empty query; A→B→A late event; cancel/shutdown; gathering versus live updates; empty unavailable index differs from empty available results; truncation retained; malformed/opaque definitions do not launch broad search; deleting a definition emits no result-file mutation.
