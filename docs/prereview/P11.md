## Findings, ranked by impact

### P11-1 — medium — main handoff omits the new live operation refusal

**Locations:** `docs/handoff/MAC_HANDOFF.md:103`, `:132`;
`Sources/HelmOperations/README.md:175` (qualified only later at `:190`).

**Wrong:** The main execution handoff describes remaining fidelity, cancellation,
journal and native-review work without stating that the default live executor
cannot currently copy, move or Trash at all. The older Operations paragraph says
ordinary directory Move/Trash remain supported. The later K34 paragraph and
`Sources/HelmFileSystem/Live/README.md:44` correctly disclose refusal, but readers
must reconcile conflicting descriptions to learn the actual default capability.
This is a documentation overstatement by omission, not a newly discovered unsafe
mutation or a request to weaken the deliberate refusal.

**Concrete failing scenario:** Compose AppEnvironment.live's LiveFileSystem with
FoundationFileCopier/OperationExecutor, then attempt an ordinary existing-file
copy or same-volume move. Executor calls the conditional API
(`Execute/OperationExecutor.swift:224`, `:232`); Live inherits the unsupported
default in `Protocol/FileSystem.swift:88`. The operation refuses with
verificationUnavailable. It does not perform a less featureful working native
copy/move. The green in-memory round trips cannot validate live feature parity.

**Exact fix:** Put the K34 capability statement in the main operation-recovery
and M8 rows: live executor copy/move/Trash unavailable; exclusive creation still
available; direct primitives are distinct from executor support. Qualify the
older README support sentence as in-memory/provider-dependent and link the
conditional contract. Keep historical test counts dated. Do not substitute
stat-then-mutate to make the documentation true.

**Evidence:** Existing K34ConditionalMutationTests includes live refusal and
source retention; K34AtomicExecutorTests covers an unadopted copier refusing
without invoking its legacy mutation. Both run in the passing P11 suite.

### P11-2 — medium — store integration instructions discard validation cancellation handles

**Location:** `Sources/HelmCore/Store/README.md:32`–35; partial supersession at
`:68`–71.

**Wrong:** The integration paragraph tells runners to return nil for validation
and refreshPaths. F6's appendix corrects refreshPaths only. K34 now also supplies
and retains validation cancellation handles. The Loading README and K34 contract
record describe the new behavior, but the store's direct consumer instructions
still tell an implementer to opt out of it.

**Concrete failing scenario:** A new effect adapter follows this paragraph,
launches validation, and returns nil. Closing a tab or shutting down the store
cannot cancel that task through the store's cancellation lane. If the adapter
also neglects its separately documented disposal obligation, validation continues
after owner teardown. Generation checks protect state publication; they do not
stop the resource consumption. Existing tests using DirectoryEffectRunner pass
because that adapter returns the handle, so they cannot validate the contrary
README recipe. This is not a reopening of P5's repaired generation bugs.

**Exact fix:** Move refreshPaths and validateNavigation out of the nil-return
list and into the required-handle list, documenting independent reload/validation
ownership and retirement on replacement, monitor retirement, disposal and shutdown.
Reserve nil guidance for genuinely synchronous work or explicitly host-owned work
with its own cancellation contract. Link DirectoryEffectRunner as the example.

### P11-3 — low — current-state inventory contradicts implemented stores and cancellation

**Locations:** `docs/handoff/MAC_HANDOFF.md:16`, `:18`, `:108`, `:111`, `:142`,

An acceptance reviewer also misses the new APIs by following the claimed complete

implementations now exist.

**Exact fix:** Refresh the current inventory and distinguish “portable component
implemented/tested” from “host wiring/native acceptance missing.” Replace the
current P7-2 deferral paragraph with the K34 implementation and remaining Mac
acceptance status. Preserve F8's report as dated history. Likewise mark older
AddressBar/FileSystem/Operations prerequisite paragraphs as superseded by K23/K34
instead of inviting duplicate contracts. Do not rewrite old run counts as new
verification evidence.

### P11-4 — low — published README test recipe fails after the F5 harness fix

and prefix the runner with `HELM_UI_SCRATCH=<that-root> python3 -B .../run.py`.

history, adding a pointer to the now-configurable harness where useful. P11 ran
