## Findings, ranked by impact

### P17-1 — Medium — same-path Inspector reuse retains an obsolete read incarnation

**Location:** `Sources/HelmCore/InspectorSessions/InspectorSessionRegistry.swift:85–92`.

**Wrong:** Per-item and summary reuse compares only ordered ItemIDs (standardized paths). Unlike follow-selection reuse, it does not reconcile incoming FileEntry values, cancel old reads, or advance generation. Changed metadata and replacement objects at the same path therefore retain old entries, enrichment, terminal size values, and callback admission. These modes also reject selectionChanged, leaving no refresh route short of closing the session.

**Concrete failing scenario:** Present `/same` with size 12 in per-item mode and retain its read token. Replace the file and present the same path with size 99. The sole effect is reuse; metadata stays 12, generation is unchanged, and the first read's subsequent final size is accepted. A summary containing the same ordered paths behaves identically. This is different from the covered follow-selection A→B→A case.

**Evidence:** A stdin-compiled executable linked against the built Core reproduced `retained metadata: 12 same generation: true` and `old callback accepted: true`. Existing reuse tests present identical entries, so they pass despite this defect.

**Exact fix:** Retain window identity while reconciling changed entry/object-identity values for every reuse mode. If clean, cancel old reads and replace the session's selection incarnation with the new request, emitting fresh reads. If dirty, route the replacement through the existing current-token keep/discard decision machinery before replacing anything. Preserve the no-restart behavior for genuinely unchanged entries. Add per-item and summary changed-entry/replaced-object tests, including old size/enrichment callbacks and dirty-draft preservation.

### P17-2 — Medium — large summary enrichment performs quadratic synchronous work

**Locations:** `Sources/HelmCore/InspectorSessions/InspectorSessionContracts.swift:76–79`; `Sources/HelmCore/InspectorSessions/InspectorSessionRegistry.swift:57–65`.

**Wrong:** Every size or enrichment callback builds the entire reads array and linearly searches it. Every accepted enrichment additionally scans all selected entries and reconstructs InspectorEditModel, including deduplication and permissions, from all enriched items so far. With N entries and one enrichment per entry this is Θ(N²), before size progress events are considered. Summary/follow-selection explicitly admit large selections without the per-item confirmation gate.

**Concrete failing scenario:** Open one summary for 100,000 files and deliver one enrichment plus one size event per file. Callback admission alone constructs about 20 billion read-request values; enrichment adds 10 billion entry lookups and repeated growing model construction. Running this synchronous reducer on the window owner blocks interaction/cancellation. Tests use at most 11 summary entries and do not exercise completed large-selection enrichment.

**Exact fix:** Build a generation-scoped ItemID→URL lookup once, and admit callbacks with constant-time session/generation/item/URL checks. Accumulate enrichment in the existing dictionary; construct the complete edit model once when all entries are enriched (edits are already gated on that condition), or maintain a separately incremental partial projection if partial metadata display is required. Avoid rebuilding whole-selection arrays for progress admission. Add deterministic work-count/scale verification covering N enrichment and size events, rather than only timing initial presentation. This finding is source-derived; no 100k benchmark claim is made.

### P17-3 — Medium — terminal envelope events leave the stream consumer running

**Location:** `Sources/HelmSearch/Sessions/SearchSessionDriver.swift:50–56,68–69`.

**Wrong:** `.finished` and `.failed` close Core event admission, but the driver ignores that transition and keeps awaiting the stream. A terminal envelope does not require the producer to also finish its AsyncThrowingStream in this public API. The driver consequently retains a live subscription/task after reporting a terminal state; subsequent events still consume work even though state rejects them.

**Concrete failing scenario:** An injected source retains its continuation, yields `.failed("metadata unavailable")`, and relies on consumer termination to release its watcher. State reports failure and `isAcceptingEvents == false`, but the consumer immediately awaits another event and its termination hook never runs until explicit cancel, replacement, shutdown, or owner release. The same occurs with `.finished`. Existing failure tests throw/finish the actual stream; they do not yield terminal envelopes on a retained stream.

**Exact fix:** After an admitted terminal envelope, cancel and release only the task whose generation still matches that event. Return from its consumption loop and let cancellation trigger stream termination cleanup. Do not treat `.results(_, isFinal: true)` as terminal: live updates must remain admitted. Add continuation-backed tests that yield `.failed`/`.finished` without finishing the stream and assert onTermination, plus a supersession test proving old cleanup cannot cancel the next request. This finding is source-derived; no native-producer cancellation guarantee is claimed.

## Other reviewed behavior and limits

- Search start/refresh allocates fresh UUIDs; cancel/shutdown invalidate admission. Weak driver capture avoids an owner-retaining loop. Ranked batch flags are retained, and empty results do not invent index availability. Native service cancellation remains an adapter obligation.
- SavedSearchOpenPlan validates Helm documents through the existing bounded AND parser; empty/vacuous criteria have no request. Finder RawQuery remains opaque. No new injection or broad-search degradation was established in this layer. Definition removal is only a URL value, with no execution.
- Inspector owner closure, decision tokens, follow-selection A→B→A, once-only enrichment, and terminal size admission have focused tests. Size projection distinguishes package/directory contents from raw metadata and preserves partial/overflow states. Overlapping selection totals are explicitly documented as supplied sums, not distinct disk usage.
- Mixed-selection editing delegates to InspectorEditModel and waits for complete enrichment. Native read cancellation, save execution, publication, and window integration remain documented follow-up, not new findings here.
